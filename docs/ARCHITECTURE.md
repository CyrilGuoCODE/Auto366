# Auto366 架构

Auto366 是一个 Electron 桌面应用。界面负责交互，主进程按业务目录组织功能，preload 连接两者。业务模块可以直接调用；`main.js` 负责创建实例、连接依赖和管理生命周期，不再增加多层转发结构。

## 整体结构

```text
界面：index.html + styles/ + renderer/
                 ⇅ 调用与事件
通信桥：preload/ → modules/register.js
                 ⇅
主进程：main.js 装配 modules/ 中的业务
  网络接入     proxy/、local-server/
  规则与执行   rules/、injection/
  答案与生成   answers/、ai/、tts/
  辅助能力     file/、resources/、speed/
  应用基础     app/、window/、config/、logging/
                 ⇅
本地文件、天学网进程、AI 供应商及远端服务
```

简单模式和专业模式共用业务和页面，只改变入口、布局与控件可见性。`renderer/pages/` 按页面组织，`panels/` 放常驻代理控件和日志，`dialogs/` 放教程等弹窗，`shell/` 管导航和主题，`services/` 提供界面通信和设置缓存。

## 模块职责与关系

| 模块 | 职责与主要关系 |
| --- | --- |
| `main.js` | 创建窗口和业务实例，连接依赖，登记接口，加载内置规则，退出时协调清理 |
| `preload/`、`register.js` | preload 暴露受控通信桥；register 登记模块接口并校验调用来源，保留旧 IPC 兼容通道 |
| `proxy/` | 代理、证书、TUN 增强模式、流量捕获及响应改写；把规则动作、答案处理和注入交给对应模块 |
| `local-server/` | 监听本机 HTTP 请求，维护唯一路径表，调用各业务的 `http.js`；业务参数由所属模块处理 |
| `rules/` | 存储、加载和管理规则，下载扩展规则集；engine 负责匹配与动作分发 |
| `injection/` | 执行 ZIP 植入和动态注入，持有自身任务、缓存、取消状态及进度窗口 |
| `answers/` | 解析不同答案格式，合并、输出、导出与分享；`learning/` 负责 AI 候选发现、提取规则生成、验证和同步 |
| `ai/`、`tts/` | AI 管理供应商配置和请求；TTS 管理语音供应商、引擎、生成与审批。内置协议签名放在 `ai/builtin-sign.js`，TTS 可直接复用该小模块 |
| `file/`、`resources/` | file 处理文件和缓存操作；resources 提供通用资源登记、下载、校验和安装，供 TTS、TUN 等使用 |
| `speed/` | 管理进程加速和加速子进程；代理处理关键请求时调用其网络保护能力 |
| `app/`、`window/` | app 管协议、更新、统计、进程监控及命令输出编码；window 管主窗口和公共窗口能力 |
| `config/`、`logging/` | config 管分模块设置及迁移；logging 统一日志格式、界面通知和可选文件记录 |

`rulesets/` 是内置规则与资源包，`resources/` 是随应用发布的静态资源和配置；两者与实现业务的 `modules/rules/`、`modules/resources/` 不同。AI 提取规则归 `answers/learning/`，注入执行归 `injection/`，不混入规则引擎。

## 如何运行

### 启动与界面调用

1. 准备脚本从 `preload/` 生成 `build/preload.js`，开发启动和打包都会先执行。
2. Electron 进入 `main.js`，初始化日志、设置、窗口与业务模块，登记 IPC，加载内置规则。代理和增强模式根据用户操作启动。
3. 页面通过 preload 调用已登记的业务接口；主进程返回结果，并用事件推送答案、日志和任务进度。界面不直接读写系统文件或执行命令。
4. 退出时停止后台服务、下载、子进程和学习任务，释放流量缓存并关闭日志。

### 请求、规则与答案

```text
天学网请求 → 代理接入 → 规则匹配 → 所属业务执行 → 返回响应
                           ├─ 响应改写或时间调整：proxy/
                           ├─ ZIP 植入或动态注入：injection/
                           └─ 语音生成：tts/
捕获的响应 / ZIP → answers/ 解析 → 合并输出 → 答案页、导出或分享
```

这是职责示意，实际执行顺序取决于规则类型。注入页面需要 AI、TTS、时间或答案接口时，请求本机 `local-server/`，由其转交业务处理；这条 HTTP 链路与桌面页面使用的 IPC 分开。

### AI 答案获取

现有解析优先。开启 AI 答案获取后，`answers/learning/` 从未识别响应及合适的 ZIP 文本中发现候选，把受限、脱敏的样本交给选定 AI，生成“请求匹配正则 + 响应答案提取正则”。启发式发现只观察已捕获的数据，不主动重放题目请求。

新规则经过结构检查和隔离执行，显示预览供用户核对后启用；ZIP 规则还限定包内文件。执行有大小、频率、并发及超时限制，规则按数据处理，不作为脚本执行。生成逻辑属于答案模块，供应商协议属于 AI 模块。

云端共享通过 `resources/answer-policy-service.json` 配置服务地址和可信验签公钥。当前配置为空，共享尚未接通；本地生成和使用不依赖共享服务。共享规则接入后仍需验签、有效期与撤销检查和本地预览，服务端另行承担鉴权、审核与签名发布。

## 状态与存储

| 数据 | 归属 |
| --- | --- |
| 主题、布局、教程状态和部分简单开关 | 界面 localStorage |
| 端口、缓存路径、AI、TTS 等复杂设置 | `%USERPROFILE%\.Auto366\settings.json`，由 config 按模块分区管理 |
| AI 获取设置、已保存规则和同步状态 | 同目录 `answer-policies.json`；临时样本和预览留在内存 |
| 用户规则、下载资源 | 同目录 `rules/`、`resources/` |
| 可选日志记录 | 同目录 `logs/`，每次启动独立文件，以启动时间为后缀 |

界面共享状态归 `renderer/state.js`，业务任务状态归所属模块。配置迁移保留备份和损坏文件保护；缓存、监听器、下载和子进程由创建它们的模块负责清理。新增功能优先扩展现有业务目录，避免让主入口、代理或规则引擎重新承担所有逻辑。
